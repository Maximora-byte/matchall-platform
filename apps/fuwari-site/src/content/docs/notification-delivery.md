通知中心保存站内副本，并可按事件类型投递到 RSS、Web Push 或邮件。不同渠道用途不同，不应把浏览器推送当作唯一的故障通知来源。

## 渠道说明

- **站内通知**：登录后可查阅，是最完整的历史记录；
- **RSS**：公开公告和状态更新，无需登录；
- **Web Push**：适合当前设备的即时提醒，需要 HTTPS、通知权限和 Service Worker；
- **邮件**：需要已验证邮箱，并由系统管理员启用邮件服务；
- **运维渠道**：仅面向管理员，不属于普通用户订阅范围。

## 开启 Web Push

1. 登录 Console 或通知中心；
2. 在通知偏好中启用浏览器通知；
3. 浏览器询问权限时选择允许；
4. 发送测试通知或等待下一条公告；
5. 在操作系统设置中确认浏览器通知未被关闭。

隐私模式、部分 iOS 安装方式以及公司浏览器策略可能限制 Push。清除站点数据或更换浏览器后，需要重新授权。

## 邮件与偏好

邮件只能发送到已经验证的邮箱。修改邮箱后需重新验证。取消某类通知只影响后续投递，不会删除站内历史。

服务故障、恢复和版本发布可进入投递队列；一般公告默认只保存站内副本，只有明确配置时才外发。临时失败会自动重试，因此同一事件可能延迟到达，但不应手工反复触发。

## 没有收到通知

依次检查：

1. 站内是否已有该事件；
2. 对应事件类型是否启用；
3. 浏览器或系统通知权限；
4. 邮箱是否已验证、垃圾邮件与过滤规则；
5. [Status](https://status.maximoraverse.org/) 是否显示通知服务异常。

若只有某一设备收不到，通常是设备权限或站点数据问题。若所有渠道都缺失，请提供事件名称、期望渠道和大致时间，不要提交浏览器订阅密钥或完整邮件头中的敏感字段。

## RSS 使用建议

RSS 不依赖登录，适合服务公告归档。使用支持 HTTPS 的阅读器订阅 Status 提供的 RSS 地址，并保留合理刷新间隔，避免分钟级高频轮询。
