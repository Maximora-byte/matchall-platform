开发者中心支持团队项目、公开或私有可见性、浏览器/CI 托管上传、外部 CDN 地址、发布 Token、Webhook 和审计记录。

## 发布前检查

在创建项目或版本前先明确项目所有者、发布渠道、支持的平台与架构，以及谁有权审批生产发布。私有或付费制品必须使用托管上传，不能把永久对象地址直接暴露给客户端。

- Owner 管理团队成员和令牌。
- Editor 创建项目和发布草稿。
- Viewer 只读取私有项目。

遵循最小权限：自动化使用独立发布 Token，不使用 Owner 的浏览器会话；人员离开团队后及时移除权限并轮换相关 Token。

## 创建项目和版本

1. 在开发者中心选择团队并创建项目；
2. 设置公开、私有或付费可见性；
3. 创建版本草稿，填写版本号、渠道和发布说明；
4. 分别上传各平台和架构的制品；
5. 核对文件大小、服务端 SHA-256 和下载名称；
6. 由有权限的成员审批并发布。

版本号应保持一致规则，避免同时出现 `v1.2.0` 与 `1.2.0`。发布说明至少包含主要变化、兼容性、升级步骤和已知问题。
- 发布 Token 按团队和 scope 限制，并可随时撤销。

## CI 托管上传

在开发者中心生成 Token 后，将它保存为 CI 的受保护 Secret。官方示例提供 GitHub Actions、GitLab CI，以及 Python、JavaScript、Go 三种上传器。上传端自动计算 SHA-256，服务端再次计算并以服务端结果为准。

所有 CI 上传先进入 draft。Owner 审批后才进入更新 API；可设置 1–100% 灰度比例。客户端应为每台安装生成稳定且不包含隐私的 client_id，更新检查时附带该值。

没有 client_id 的旧客户端只接收 100% 发布。快速回滚会立即将版本从项目页、下载入口和更新 API 中移除。

## 灰度发布与回滚

建议先向内部设备或较小比例开放，再逐步扩大。每一步都观察下载成功率、更新失败率、崩溃和用户反馈。不要仅因为下载次数增长就自动扩大灰度。

发现严重问题时执行快速回滚，并确认项目页、直接下载和更新 API 都不再返回问题版本。回滚后保留审计记录，修复版使用新版本号，不覆盖已经发布的制品。

## 私有对象存储

私有或付费制品必须使用托管上传。本地存储和 S3/R2 使用相同授权边界；S3/R2 下载在权限校验后生成短期签名 URL，永久对象地址不会暴露给浏览器。未配置对象存储凭据时平台安全回退到本地存储。

Webhook 使用 HMAC-SHA256 签名。接收端必须校验时间戳、事件 ID 和签名，并按事件 ID 幂等处理。

## Webhook 安全清单

- 使用原始请求体计算签名，不要先重新序列化 JSON；
- 对时间戳设置合理容差，拒绝过旧请求；
- 记录事件 ID，并让重复事件安全返回成功；
- Secret 只保存在密钥管理或 CI Secret 中；
- 日志不得记录签名 Secret、发布 Token 或完整授权头；
- 接收端失败时返回明确状态码，由平台按策略重试。

## 发布失败排查

浏览器上传失败时记录项目、版本、文件大小和时间。CI 失败时先区分 401/403 权限问题、409 状态冲突、413 大小限制和 5xx 服务异常。不要通过无限重试绕过审批或重复创建版本。

发布完成后，从未登录窗口检查公开项目；对私有项目使用普通 Viewer 账户验证授权边界，并下载一次制品核对 SHA-256。
