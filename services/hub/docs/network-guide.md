MatchAll Network 为已开通用户提供线路、订阅和设备管理。订阅地址与设备令牌等同于访问凭据，任何拿到它的人都可能消耗你的流量。

统一账户用于登录，套餐、流量和设备权限仍由 Network 管理。注册或登录成功不代表已有有效套餐；只配置原服务为当前账户提供的客户端与线路。

## 获取配置

1. 打开 [Network 登录入口](https://proxyservice.maximoraverse.org/login)，按页面提示完成统一登录；
2. 在原服务确认套餐、到期时间、剩余流量和设备限制；没有有效套餐时，先查看开通、价格与退款说明，再决定是否购买；
3. 按客户端类型复制订阅或使用页面提供的导入方式；
4. 回到客户端刷新配置，确认节点列表出现；
5. 先用普通网页完成连通性测试。

不要把完整订阅地址粘贴到测速网站、公开 Issue、群聊或截图中。怀疑泄露时，使用原服务提供的重置或撤销入口；没有相应入口时联系官方支持。仅删除消息不能使已经泄露的地址失效。

## 选择线路

不要只看一次测速峰值。更可靠的判断顺序是：

1. 连续延迟和抖动；
2. 丢包和连接失败率；
3. 常用网站的 TCP/TLS 建连与首字节时间；
4. 最后才是大文件吞吐量。

移动网络、家庭宽带和公司网络的最佳线路可能不同。视频、网页和软件更新也可能适合不同线路。建议保留一个稳定备用节点。

## 更新与设备管理

- 客户端应定期刷新订阅，但不要设置异常高频率；
- 更换手机或重装系统后，如原服务提供设备管理入口，核对并移除不再使用的旧设备；
- 套餐、流量、设备数和到期时间以账户页显示为准；
- 节点临时消失时先刷新订阅并查看 Status，不要反复重新导入。

[Console](https://console.maximoraverse.org/console) 中的用量、设备数和到期时间是只读快照。先看快照更新时间；等待同步、数据过期或同步异常不等于套餐失效。刷新 Console 不会触发业务同步，也不能证明某条线路已经连通。

## 常见故障

**所有线路都连接失败**：先关闭并重新开启客户端核心，确认系统时间、网络和订阅是否有效，再查看 [Status](https://status.maximoraverse.org/)。

Status 的 Network 检查仅验证公共配置 API 可响应，不验证节点连通性、订阅刷新或端到端流量。状态正常时仍需根据具体错误核对客户端和原服务。

**只有一个节点失败**：切换备用节点并记录节点名、运营商、发生时间和错误类型；不要提交节点 URI。

**延迟正常但网页慢**：如客户端提供相应诊断，可比较 DNS、TCP/TLS 建连和首字节时间（TTFB）。先核对客户端代理模式、系统代理设置以及是否同时启用了多个网络客户端；每次只调整一项自己确认有误的设置，保留原值并复测。不要为排查直接关闭防火墙或安全软件；受管理设备上的配置应由管理员处理。

**订阅刷新失败**：确认账户未过期、设备数未超限，重新从账户页复制订阅。不要手工修改 Token。

**移动网络可用、Wi-Fi 不可用**：先在同一设备、客户端和节点条件下对比，确认 Wi-Fi 本身能正常访问网络。差异可能涉及本地网络、IPv6、MTU 或防火墙，但不能仅凭这一现象确定原因。可按原服务与客户端提供的选项测试备用线路；不要未经确认修改 MTU 或防火墙规则。

**Console 与 Network 数据不同**：核对当前账户和快照时间，最新套餐、用量及权限以 Network 页面为准。不要把汇总异常当作节点故障，也不要因此重复购买或创建账户。

## 提交问题时提供

- 客户端名称和版本；
- 操作系统版本；
- 网络类型和运营商；
- 出错时间与节点显示名称；
- 已打码的错误提示或 HTTP 状态码。

通过[官方支持](https://www.maximoraverse.org/contact/)反馈，不要提交完整日志、订阅地址、节点 URI、Token、账户凭据或个人 IP。
