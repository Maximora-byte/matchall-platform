MatchAll DNS 使用指南 · 更新于 2026 年 9 月 27 日

一个账号共用一套令牌与策略，可按设备选择 DoH、DoT 或 DoQ，并通过 IPv4 或 IPv6 连接。不需要手工拼接地址，也不需要为每台设备创建账号。

1. 先选择接入方式

  • Android 系统私人 DNS：选 DoT。填写账户页的“DoT 主机名”，使用 TCP 853。
  • 浏览器、Apple 描述文件及支持自定义模板的 Windows：选 DoH。使用完整 HTTPS 地址，通常走 TCP 443。
  • 明确支持 DNS over QUIC 的客户端：可选 DoQ。使用账户页的 DoQ 地址，走 UDP 853。不支持时改用 DoH 或 DoT。

三种协议共用账号停用、配额、过滤策略和统计。协议变化不代表过滤开关发生变化，也不保证速度提升或连接永不中断。

本页不展示可直接使用的个人地址。请从自己的账户页复制；不要拿别人的截图或地址进行配置。

IPv4 / IPv6 双栈怎么配置？

账号入口同时支持 IPv4 和 IPv6。大多数设备只需填写账户页提供的 DoH 地址、DoT 主机名或 DoQ 地址；系统会解析 A/AAAA 并选择当前网络可用的连接，不需要建立两个账号。

  • IPv6 服务器：{{ dns_ipv6 }}

只有 Windows 等要求同时填写“服务器 IP”和“DoH 模板”的界面才需要复制这些 IP。IPv4 和 IPv6 都使用同一个带令牌的 DoH 模板。浏览器、Android 私人 DNS和 DoQ 客户端应继续填写主机名或完整地址，不能用裸 IP 替代 TLS 主机名。

Apple 描述文件同时携带两个服务器地址。若当前网络没有 IPv6，设备仍可使用 IPv4；具体选路和失败回退由操作系统或客户端决定，严格加密模式不会回退到明文 DNS。

`dns-hk` 和 `dns-backup` 是独立服务入口，不是账号令牌的备用填写项。账号设备应始终使用账户页生成的专属地址，否则会绕过账号停用、配额、过滤和统计。

2. Android：系统私人 DNS（DoT）

  1. 登录 DNS 账户页，点击“复制 DoT 主机名”。
  2. 打开系统设置，搜索“私人 DNS”或“私有 DNS”。常见路径为“网络和互联网 → 私人 DNS”，不同品牌名称可能不同。
  3. 选择“私人 DNS 提供商主机名”，粘贴复制的主机名并保存。
  4. 切换一次 Wi-Fi／移动网络，检查系统是否提示无法连接，再尝试打开网站。

这里只填主机名：不要添加 https://、quic://、:853 或 /dns-query/。不要选择“自动”来代替指定提供商。

若当前网络拦截 TCP 853，严格私人 DNS 可能导致无法解析。可以临时恢复原设置，再使用支持自定义 DoH 的客户端；恢复原设置后就不再保证经过 MatchAll。

应用自带的 DNS、VPN 或代理可能覆盖系统 DNS。连接正常不代表每个应用都使用同一解析入口。

3. iPhone、iPad、Mac：DoH 描述文件

  1. 用 Safari 登录账户页，点击“下载 Apple 描述文件”。
  2. 在系统设置中打开“已下载的描述文件”。iPhone／iPad 常见路径是“通用 → VPN 与设备管理”；Mac 可在设置中搜索“描述文件”。
  3. 检查内容后安装，再尝试解析和访问网站。

描述文件同时包含 IPv4 和 IPv6 服务器地址，但仍只使用同一个账号 DoH URL 与令牌。文件未签名，仅包含 DNS 设置，不包含根证书、VPN 或 MDM。请仅从本站下载。需要撤销时，在系统设置删除该描述文件；无需删除账号。

此方法使用 DoH，不是 DoQ。具体菜单和应用覆盖行为随系统版本变化；尚未在所有设备型号上逐一实测。

4. 浏览器与 Windows：DoH

Chrome／Edge／Firefox

  1. 在账户页复制完整的“账号专属 DoH 地址”。
  2. 在浏览器设置中搜索“安全 DNS”或“DNS over HTTPS”。
  3. 选择自定义提供商，粘贴完整地址。路径与令牌必须保留。
  4. 保存后按下方方法验证。

浏览器会通过主机名自动选择 IPv4 或 IPv6，通常不需要填写服务器 IP。浏览器设置通常只影响该浏览器；若允许失败时回退到系统 DNS，就不能保证所有查询都经过本站。

Windows 11

  1. 把账户页显示的 IPv4 地址填入 IPv4 首选 DNS。
  2. 网络已有 IPv6 时，把账户页显示的 IPv6 地址填入 IPv6 首选 DNS。
  3. 两个协议的 DNS over HTTPS 均选择手动模板，并填写同一个完整账号 DoH 地址。
  4. 需要严格加密时关闭“失败时使用未加密请求”。

不同 Windows 版本可能不提供自定义模板；这种情况下使用支持自定义 DoH 的浏览器或客户端。仅填写服务器 IP 并不能启用账号认证或加密 DNS。

5. 支持 DoQ 的客户端

  1. 确认客户端明确支持 DNS over QUIC（DoQ），而不只是 HTTP/3 或 QUIC 代理。
  2. 复制账户页的 DoQ 地址，在客户端的 DNS 上游设置中导入。
  3. 若不接受 quic:// 格式，请分别填写账户主机名、端口 853，协议选 DNS over QUIC。
  4. 若客户端要求 TLS Server Name／SNI，填写同一个完整账户主机名。保持证书校验开启，不要勾选“跳过证书验证”。

DoQ 需要网络允许 UDP 853。无法连接时可尝试 DoT 或 DoH；不要把 DoQ 地址当成代理节点或 Clash 订阅导入。“Smart 专用订阅”是另一个功能，与这里的 DNS 接入无关。

协议已通过真实 DoQ 客户端库与外部服务器验证；不代表每个手机应用的界面或导入格式都已实测。

6. 过滤开关与自建递归有什么关系？

换成 DoT／DoQ，不会自动启用 modDNS。未开通自定义过滤的账号继续走原解析链路；提前保存规则也不会切换。

主动点击“开通自定义过滤”后，账号请求才会使用个人过滤策略。默认启用 HaGeZi Multi Pro 和 HaGeZi TIF Medium：综合过滤广告与追踪，并补充恶意软件、钓鱼、诈骗和命令控制等安全威胁。还可管理允许／阻止规则、其他可选列表、分组、服务屏蔽与重绑定保护。

modDNS 未拦截的请求交给自建递归解析器，由它向 DNS 权威服务器查询并验证 DNSSEC。它不是设备需要单独配置的公共 DNS 地址。设备到入口的查询已加密，但递归到权威服务器的链路通常不加密；DNSSEC 提供数据真实性验证，不是加密。

个人过滤后端故障时返回失败，不会自动回退到缺少个人规则的旧上游。DNS 过滤也无法保证屏蔽所有应用广告、缓存 IP 或同域名内容。

7. 如何验证与排查

  1. 确认地址来自当前账户页，且账号未停用；重置过令牌的话，重新复制所有设备配置。
  2. 访问一个网站后，在账户页查看请求统计。缓存可能使一次访问不产生新查询，统计也可能有短暂延迟，不能只凭网页打开就认定配置成功。
  3. 需要进一步核对时，可登录后主动开启“查询记录”，再请求一个未缓存域名。完成检查后可以关闭并清空。查询记录默认不启用。
系统提示“无法连接私人 DNS”

检查是否只填了 DoT 主机名，是否多了空格、前缀或路径。核对设备时间，尝试另一网络；TCP 853 被拦截时可改用 DoH。不要关闭证书校验。

DoQ 无法连接，但 DoH 正常

可能是客户端不支持 DoQ、导入格式不符，或当前网络限制 UDP 853。检查协议、SNI 和端口，必要时使用 DoH／DoT。DoQ 不是必需项。

连接成功，但过滤或统计没有变化

检查是否真正开通过滤、规则是否保存成功，以及浏览器自带 DNS、VPN／代理是否绕过系统设置。清理缓存或换一个未缓存域名后再检查；普通 NXDOMAIN 不等于被规则拦截。

提示证书错误

先检查设备时间与主机名，再联系支持。当前证书由运营方人工续期，平台检查临近到期状态；用户不需要购买、上传或手动安装服务器证书。不要以跳过验证来解决。

如何恢复原 DNS

Android 恢复原私人 DNS 设置；Apple 删除本服务描述文件；浏览器恢复原安全 DNS 提供商；DoQ 客户端恢复原上游。修改客户端设置不会注销账号，但后续查询可能不再经过 MatchAll 的规则。

联系与支持

反馈时提供设备、客户端版本、使用协议、发生时间和已打码的错误提示。不要提交完整个人地址、令牌或描述文件。

8. 令牌与查询隐私

  • DoH 地址、DoT 主机名、DoQ 地址都包含账号访问凭据。自己的设备可以共用，但不要公开分享。
  • “重新生成账号令牌”会使所有旧协议地址失效。之后需要重新配置所有设备，并重新下载 Apple 描述文件。
  • 加密 DNS 不等于完全匿名；引导 DNS 查询、TLS 主机名和其他连接元数据可能可见。
  • 逐条查询记录默认关闭；用户明确同意后可选择 1 小时、24 小时或永久保留。记录保存在数据盘，不保存客户端 IP、令牌或完整 DNS 答案；关闭时会清空该账号明细。
  • 聚合统计永久保留。关闭查询明细不会停止必要的聚合统计；原解析链路的上游也可能有独立日志。
